Architecture Overview

How the Background Worker Operates

The worker runs autonomously in the background via Linux Cron or Systemd daemon (even when all users are completely logged out of Roundcube). It connects to IMAP, triages unread mail with Gemini 3.8 Flash, tags emails with organizational labels, replicates learned answers, and prepares draft replies.

Step 1 • Triage

Security & Priority

Gemini analyzes urgency, sender intent, and tags with Roundcube IMAP label flags ($Label1 - $Label5).

Step 2 • Memory

Knowledge Replication

Checks AI memory for previously verified answers to common client questions and replicates them consistently.

Step 3 • Drafts

Draft Generation

Generates executive draft replies and saves them directly into your IMAP Drafts folder (ready for review).

Step 1

Verify System Prerequisites

Run the following command on your server to verify that your PHP CLI environment satisfies all prerequisites.

bash 
/usr/bin/php -v
/usr/bin/php -m | grep -E "openssl|curl|json|mbstring|pcntl"
Requirements Checklist:
  • PHP CLI: Version 8.0 or newer (8.1, 8.2, 8.3 fully supported).
  • openssl: For secure IMAP TLS/SSL connections.
  • curl: For Google Gemini API communication.
  • json & mbstring: For payload parsing and UTF-8 handling.
  • pcntl: Optional, used for graceful shutdown signals when running in daemon mode.
Step 2

Configure Worker Settings in config.inc.php

Ensure your plugin configuration file exists in your plugin directory and configure the background worker options.

Initialize configuration from distribution template:

bash 
cd /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai
test -f config.inc.php || cp config.inc.php.dist config.inc.php

Snippet to verify/add inside config.inc.php:

php — config.inc.php 
// 1. Google Gemini API Key & Model
$config['lifeprisma_ai_gemini_api_key'] = 'YOUR_GOOGLE_GEMINI_API_KEY';
$config['lifeprisma_ai_gemini_model'] = 'gemini-3.8-flash';

// 2. Message Triage Labels (roundcube-labels integration)
$config['lifeprisma_ai_triage_labels_enabled'] = true;
$config['lifeprisma_ai_triage_label_map'] = [
    'action_required_high' => '$Label1', // Belangrijk / Important (Red)
    'action_required'      => '$Label4', // Te doen / To Do (Blue)
    'meeting'              => '$Label2', // Werk / Work (Orange)
    'follow_up'            => '$Label4', // Te doen / To Do (Blue)
    'fyi'                  => '$Label5', // Later (Violet)
    'scam'                 => '$Label1', // Warning
];

// 3. 24/7 Background Worker Accounts Configuration
$config['lifeprisma_ai_worker_imap_host'] = 'ssl://localhost:993';
$config['lifeprisma_ai_worker_accounts'] = [
    [
        'email' => 'koen@thechargegrid.com',
        'password' => 'your_secret_email_or_app_password',
        'drafts_folder' => 'Drafts',
    ],
];
Step 3

Test with Safe Dry-Run Mode

Before creating the cron job, test the worker in safe dry-run mode. This verifies IMAP connectivity and Gemini API responses without modifying anything in your mailbox.

bash 
cd /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai
/usr/bin/php bin/worker.php --account=koen@thechargegrid.com --dry-run --verbose
Safe Testing Guarantee: In --dry-run mode, emails are never marked read, labels are not permanently stored, and no drafts are deposited onto the IMAP server. You can view the simulated output in the Dry-Run Simulator Tab.
Step 4

Setup Permissions, Log File & Linux Cron Job

Set permissions, initialize the log file, and schedule the background execution in crontab.

1. Set Execution Permissions:

bash 
chmod +x /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/bin/worker.php

2. Initialize Log File:

bash 
touch /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log
chmod 0640 /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log

3. Edit Crontab:

bash 
# Open your crontab editor (do NOT use -u on Combell / shared hosting)
crontab -e

4. Crontab Entry to Add:

cron 
*/3 * * * * /usr/bin/php /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/bin/worker.php >> /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log 2>&1
Step 5

Configure Log Rotation (Optional but Recommended)

Prevent log files from growing indefinitely on production servers.

Create /etc/logrotate.d/roundcube-ai-worker (requires root/sudo):

logrotate 
/data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log {
    weekly
    missingok
    rotate 8
    compress
    delaycompress
    notifempty
    create 0640 mobilitypulsecom mobilitypulsecom
}

Verify logrotate syntax:

bash 
logrotate -d /etc/logrotate.d/roundcube-ai-worker

Quick Deployment

Automated Server Setup Script

Execute this single self-contained script on your server. It will check prerequisites, set executable permissions, initialize log files, run a safe dry-run test, and print the exact crontab entry for you.

bash — setup-worker.sh 
#!/usr/bin/env bash
# ==============================================================================
# Gemini Executive Assistant Worker — Automated Installer
# Target: /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai
# Generated dynamically for: mobilitypulsecom / koen@thechargegrid.com
# ==============================================================================

set -e
echo "========================================================="
echo "Gemini Executive Assistant — Cron Worker Setup"
echo "========================================================="

PLUGIN_DIR="/data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai"
PHP_BIN="/usr/bin/php"
LOG_FILE="/data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log"
USER="mobilitypulsecom"
GROUP="mobilitypulsecom"

# 1. Check PHP
echo "[1/5] Checking PHP CLI..."
if ! command -v "$PHP_BIN" &> /dev/null; then
    echo "ERROR: PHP binary not found at $PHP_BIN"
    exit 1
fi
echo "  Found PHP version: $("$PHP_BIN" -r 'echo PHP_VERSION;')"

# 2. Check directory
echo "[2/5] Checking plugin directory..."
if [ ! -d "$PLUGIN_DIR" ]; then
    echo "ERROR: Plugin directory $PLUGIN_DIR does not exist!"
    exit 1
fi

# 3. Permissions
echo "[3/5] Setting permissions..."
chmod +x "$PLUGIN_DIR/bin/worker.php"
mkdir -p "$(dirname "$LOG_FILE")"
touch "$LOG_FILE"
chmod 0640 "$LOG_FILE"
echo "  Worker binary and log permissions set."

# 4. Dry Run Test
echo "[4/5] Testing worker in dry-run mode..."
"$PHP_BIN" "$PLUGIN_DIR/bin/worker.php" --dry-run || {
    echo "WARNING: Dry-run test exited with a warning. Check config.inc.php!"
}

# 5. Crontab reminder
echo "[5/5] Setup complete! Add this line to your crontab (run: crontab -e):"
echo "---------------------------------------------------------"
echo "*/3 * * * * $PHP_BIN $PLUGIN_DIR/bin/worker.php >> $LOG_FILE 2>&1"
echo "---------------------------------------------------------"
echo "Done! Monitor with: tail -f $LOG_FILE"
Alternative: 24/7 Daemon

Systemd Background Service

If your server supports root systemd services and you prefer a continuous background daemon rather than cron, configure this service unit.

1. Service Unit: /etc/systemd/system/lifeprisma-ai-worker.service

systemd — lifeprisma-ai-worker.service 
[Unit]
Description=Gemini Executive Assistant 24/7 Background Worker (Autonomous Mode)
After=network.target dovecot.service

[Service]
Type=simple
User=mobilitypulsecom
Group=mobilitypulsecom
WorkingDirectory=/data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai
ExecStart=/usr/bin/php /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/bin/worker.php --daemon --interval=60
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

2. Enable and Start Systemd Daemon:

bash 
systemctl daemon-reload
systemctl enable lifeprisma-ai-worker.service
systemctl start lifeprisma-ai-worker.service

# Check status and live log stream
systemctl status lifeprisma-ai-worker.service
journalctl -u lifeprisma-ai-worker.service -f

Diagnostics

Common Issues & Troubleshooting Matrix

Click any issue below for immediate diagnosis and customized resolution commands.

Cause: Host port mismatch or strict SSL certificate verification on localhost.

  • Check whether your mail server listens on ssl://localhost:993 (implicit TLS) or tcp://localhost:143 (STARTTLS).
  • If your hostname certificate requires fully qualified domain name, change $config['lifeprisma_ai_worker_imap_host'] from localhost to your server FQDN (e.g., ssl://mail.thechargegrid.com:993).
bash — test port 
nc -zv localhost 993 || nc -zv localhost 143

Cause: Mail servers use different folder naming conventions depending on locale and server configuration:

  • English: Drafts
  • Dovecot namespace prefix: INBOX.Drafts
  • Dutch: Concepten or INBOX.Concepten

Set 'drafts_folder' => 'Drafts' in your account configuration array in config.inc.php.

Cause: The user running the cron job does not have write permissions to the destination log file.

bash — fix permissions 
touch /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log
chown mobilitypulsecom:mobilitypulsecom /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log
chmod 0640 /data/sites/web/mobilitypulsecom/subsites/webmail.thechargegrid.com/plugins/lifeprisma_ai/worker.log

If you prefer not to store individual account passwords, configure Dovecot Master Users:

php — config.inc.php 
$config['lifeprisma_ai_worker_imap_host'] = 'ssl://localhost:993';
$config['lifeprisma_ai_worker_dovecot_master_user'] = 'masteradmin';
$config['lifeprisma_ai_worker_dovecot_master_password'] = 'your_master_secret';
$config['lifeprisma_ai_worker_accounts'] = [
    ['email' => 'koen@thechargegrid.com', 'drafts_folder' => 'Drafts'],
];
